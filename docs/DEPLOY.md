# Deploying StudyFlow AI

The app is two pieces: a React SPA (static build) and an Express API backed by
MongoDB. That second piece cannot live on Vercel's serverless functions, so the
working production setup is:

| Piece | Host | Why |
| --- | --- | --- |
| Database | MongoDB Atlas (free M0) | persistent, reachable from anywhere |
| API + SPA | Render (Docker web service) | long-running Node process, one origin, no CORS |
| UI preview (optional) | Vercel | static `frontend/dist`, points at the Render API |

## 1. Database — MongoDB Atlas

1. Create a free M0 cluster at https://cloud.mongodb.com.
2. Database Access → add a user with a strong password.
3. Network Access → allow `0.0.0.0/0` (or Render's outbound IPs).
4. Copy the connection string and add the database name: `.../studyflow`.

## 2. API + UI on Render (recommended)

1. Push this repository to GitHub.
2. Render → New → Blueprint → select the repo. `render.yaml` is picked up
   automatically (Docker, health check `/api/health`).
3. Set the environment variables it asks for:
   - `MONGO_URI` — the Atlas string from step 1
   - `PUBLIC_URL` — `https://<your-service>.onrender.com` (after first deploy)
   `JWT_SECRET` is generated by Render.
4. Deploy. The Docker image builds `frontend/dist` and the server serves both the
   SPA and `/api` from the same origin.
5. Verify: `https://<your-service>.onrender.com/api/health` returns
   `{"status":"ok","database":true}`.

## 3. UI on Vercel (optional, same API)

```bash
cd frontend
npx vercel link
npx vercel env add VITE_API_URL production   # https://<your-service>.onrender.com/api
npx vercel --prod
```

`frontend/vercel.json` already sets the SPA rewrites so deep links work.
Because the UI is now on a different origin, add it to the API's
`CORS_ORIGINS` (comma separated) on Render.

## 4. CLI deploy from this machine

Requires your own Vercel login (`npx vercel login`) — nobody else can
authenticate as you.

```bash
cd ~/Downloads/StudyFlow/frontend
npm ci && npm run build
npx vercel --prod
```

## Post-deploy checklist

- [ ] `/api/health` reports `database: true`
- [ ] register → login → refresh (session survives)
- [ ] create a subject, add a unit and a topic
- [ ] generate a plan, complete a focus session, watch the dashboard update
- [ ] upload a file, then open it again while logged out (must be 401)
- [ ] forgot-password returns the generic message
